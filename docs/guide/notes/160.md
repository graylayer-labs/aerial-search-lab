# #160 Reshape the repo into a lab of approaches

Set out to: turn one thesis-shaped package into a lab where approaches A, B and C share one evaluation, and rename the repo `aerial-search-lab` (owner, 2026-10-23).
Chose: a uv workspace, with the data, folds, frame selection, metrics, run records and cloud launcher in `shared/aerial_search`, one package per approach in `projects/`, and a lazy command registry so every command keeps its name, in a cloud job too.
Expected before running: a pure move, with no behaviour change.
Surprising:
- Every hard-coded `parents[N]` root lookup moved one or two levels deeper. The one that mattered was the AWS settings lookup: at the wrong depth it falls back silently to the owner's administrator sign-in. A test now checks that every root lookup lands on the folder that holds `uv.lock`.
- `uv export --no-emit-project` emits workspace members as `-e ./...` lines, which pip refuses as constraints, so the cloud job needed `--all-packages --no-emit-workspace`.
- Passing tests were not the proof. The checks that counted were mechanical: each moved file identical or changed only in its imports, and every command's flags and every results table byte-identical.
- The 400-line PR gate turned 7 steps into 11 PRs, stacked, each rebased and checked to have the exact tree the lead tested.
Sources: PRs #162 to #183; docs/decisions.md lines dated 2026-10-23; shared/aerial_search/tests/test_layout.py and test_boundaries.py.
